# 2026-09-19 — Arranque del proyecto y Fase 1 completa

Sesión inicial. De cero a un coding agent que corre sobre LLM local y completa el ciclo
`usuario → harness → LLM → tool call → ejecución → ToolResult → LLM → respuesta`.

## Entorno

| | |
|---|---|
| GPU | dedicada, 24 GB libres al empezar (no es un requisito: ver PROJECT_STATE) |
| Python | 3.14.7 gestionado por `uv` (no hay python del sistema en PATH) |

## Lo que se construyó

- `models.py` — todo el modelo de datos.
- `providers/base.py` + `providers/ollama.py` — Protocol de un método + adapter real.
- `tools/base.py` + `tools/fs.py` — registry, executor, `list_files`, `read_file`, `safe_path`.
- `harness/loop.py` — agent loop con 5 condiciones de terminación.
- `harness/prompt.py` — system prompt.
- `cli.py` — `health` y `ask` con observabilidad del loop en vivo.
- 24 tests.

## Problemas encontrados y cómo se resolvieron

### 1. Ollama no devuelve `id` en las tool calls

`/api/chat` devuelve `{"function": {"name": ..., "arguments": {...}}}` sin `id`. OpenAI y
Anthropic sí lo traen.

El harness correlaciona `ToolCall` ↔ `ToolResult` por `call_id` (nunca por posición, porque con
ejecución paralela el orden de finalización no es el de pedido). Sin id no hay correlación.

**Resuelto en el provider:** `OllamaProvider._next_call_id()` sintetiza ids `call_NNN_hexhex`.
Es el borde correcto: el harness declara la garantía que necesita y el adapter la cumple como
pueda para su backend. El loop no se entera.

Alternativa descartada: usar el endpoint OpenAI-compatible `/v1/chat/completions`, que sí devuelve
ids — pero no expone `options.num_ctx` ni `think` de la misma forma.

### 2. `num_ctx` chico y truncado silencioso

Ollama trunca el prompt **por la izquierda y sin avisar** si excede `num_ctx`, comiéndose el
system prompt. El default por modelo suele ser 2048-4096.

**Resuelto:** `num_ctx` se manda explícito en `options` de cada request (32768).

### 3. qwen3 piensa por defecto

Es un modelo razonador: el razonamiento va a `message.thinking` en vez de `content`, y agrega
latencia grande por turno.

**Resuelto:** el provider manda `think: false`. Si el modelo no lo soporta, detecta el error,
lo recuerda para la sesión y reintenta sin el campo.

### 4. `done_reason` no distingue tool calls

Ollama manda `done_reason: "stop"` aunque la respuesta traiga tool calls.

**Resuelto:** `StopReason.TOOL_USE` se deriva de la **presencia** de tool_calls, no del
`done_reason`.

### 5. La consola de Windows mata el proceso

`UnicodeEncodeError: 'charmap' codec can't encode character '✓'` — cp1252 no puede imprimir
`✓`. El agente "fallaba" por un motivo que no tenía nada que ver con el agente.

**Resuelto:** `_init_console()` reconfigura stdout/stderr a UTF-8; si no puede, las marcas caen a
ASCII (`[ok]`, `[x]`, `->`).

### 6. El agente no leía archivos (el hallazgo importante)

Primera corrida real: 2 turnos, **sólo `list_files`**, cero `read_file`. Respondió infiriendo de
los nombres de archivo, con "posiblemente" y "probablemente" por todos lados, y dictaminó que
`cli.py` era el archivo más importante **por su tamaño en KB**.

El harness funcionó perfecto. Falló el *grounding* del modelo.
Taxonomía: `CONTEXT`/`MODEL`, no `TOOL` ni `EXECUTION`.

**Arreglo:** system prompt reescrito de "no inventes" a un método explícito de 3 pasos con
`read_file` obligatorio, y una regla accionable en vez de abstracta:

> PROHIBIDO usar "posiblemente", "probablemente", "parece que". Si te sale una de esas palabras
> es la señal de que te falta un `read_file`: pedilo en vez de escribirla.

**Antes:** 2 turnos, 0 archivos leídos, 2419 tokens, 47.0s.
**Después:** 3 turnos, 3 archivos leídos en paralelo, 7946 tokens, 12.8s.

Es más rápido pese a gastar 3x tokens porque la primera corrida se fue en generar una respuesta
larga y especulativa.

El hedging sobrevive, pero **sólo sobre archivos que no leyó** — eso ya no es alucinación, es
calibración correcta.

**Límite conocido:** el prompt mejora el grounding, no lo garantiza. La garantía dura es un
verifier de trayectoria (Fase 3) que rechace la respuesta final si no se leyó ningún archivo.
